# PCR 7 — the discovery sequence earns Tick composition

The useful abstraction is now visible only because the badge sequence was replayed first.

A **Tick** is one progressive claim over a named input checkpoint that retains:

- the evidence it consumed;
- the claim/output it produced;
- the residue it did not explain;
- a render fragment;
- a receipt fragment.

For the badge case, the earned Tick sequence is the actual discovery history:

1. live masks/components/family/digit-read/physical composition/subtraction;
2. observe dark digit counters surviving that claim;
3. experimental custody fix for those already-observed dark components;
4. residual digit matching proves remaining structure still carries digit identity;
5. digit-muted alignment reveals stable shared corners/rim;
6. per-instance lane keeps the right rail unexplained.

A **Progressive Compositional Render** is an ordered composition of those Ticks. Render and CLI text are projections of the same Tick trace; both must reference the same input identity, coordinate frame, evidence population, claimed custody, anomaly ordering, and unexplained residue.

The smallest earned execution composition remains `fork(...).compare(...)`:

- fork from one prepared badge checkpoint;
- keep `defaultLive` immutable;
- run the experimental PCR composer as a sidecar;
- project both into the same measurement space;
- compare paired outputs and unexplained residuals;
- do not auto-select, merge, or mutate the pin.

This is the handoff: the abstraction is the compression of the empirical sequence, not a framework imposed before the sequence existed.
