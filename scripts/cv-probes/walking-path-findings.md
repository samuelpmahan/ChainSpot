# Walking-path pixel classification — exploratory benchmark findings

Date: 2026-08-12. Fixture: `resources/ThrownRounds/IMG_5612.png` (zoomed
played-round UDisc screenshot, the only capture pair we have with a walking
path; `IMG_5613.png` is the same round at full-course zoom). This is a
single-fixture spike: every number below is **held-out spatial performance on
one image**, not generalization to unseen captures. It is independent of the
paused fairway-ribbon/centerline work and does not touch it.

## TL;DR

**The walking path is trivially separable — the opposite result from the
fairway ribbon.** Unlike the ribbon (translucent, soft-edged, no Canny edge),
the walking path renders as a hard-edged, near-opaque two-tone stroke: a
saturated purple casing (RGB ≈ 91,49,174 at the edge, ≈ 136,102,203 mid)
around a near-white lavender core (≈ 250,249,253), total width ~20–26 px at
IMG_5612's zoom. Every classifier tried, including plain logistic regression
and a one-line color rule, reaches F1 ≥ 0.96 on held-out spatial regions;
the best combos reach 0.999. Stage-2 reconstruction (close → open → drop
small blobs → skeletonize) turns the best masks into an essentially
connected skeleton of the whole path (2 components, 99.9 % of skeleton
pixels within 5 px of ground truth). This signal is ready for a simple
production implementation; no further model sophistication is warranted.

## Setup

- **Annotation** (`resources/walking-path/IMG_5612-walking-path-labels.png` +
  `-regions.json`, regenerated by `walking_path_make_annotation.py`): paletted
  label PNG (0 background / 1 path / 2 ignore-ring), ~115 k path pixels, plus
  six disjoint spatial region boxes A–F covering every path pixel.
- **Provenance caveat**: the path mask was bootstrapped with the color
  heuristic `min(R−G, B−G) > 25` + morphological closing, then **visually
  verified** against the image (it covers exactly the visible stroke,
  image-wide, and excludes overlaid UI glyphs). The ground truth is correct
  regardless of its seed, but the benchmark's `rule-purple-delta` baseline is
  by construction close to that seed. The strongest evidence of separability
  comes from models on independent representations (LAB, HSV), which beat the
  seed rule.
- **Split**: train on regions A (top-left run), B (left vertical, brown
  grass), D (top loop over gray ribbon/road); test on C (bottom run: scrub,
  blue shot line, badge "2"), E (mid strand + vertical over green putting
  circle), F (bottom strand: scrub, icons). 25 k pos / 50 k neg pixels
  subsampled per split, fixed seed. Nearby-pixel correlation across the
  train/test boundary rows exists but the regions are large (hundreds of px
  apart on average), so this detects blatant memorization, nothing more.
- **Benchmark**: `walking_path_benchmark.py --out <dir>` (~35 s), writes the
  tables plus full-image diagnostic contact sheets.

Feature sets: `lab+Δ` = [L, a, b, ΔL, Δa, Δb, S] where Δ = pixel − 31×31
local mean (the conceptual vector from the task brief — it is indeed the best
cheap representation). `full` adds cos/sin hue, local σ(L), |∇L|.

### What the diagnostics show (`walking-path-results/*.png`)

- **lab+Δ linear models**: visually perfect image-wide; only residual errors
  are a few pixels at UI-glyph rims (droplet markers, badge borders).
- **rule-purple-delta**: correct on the stroke but sprays small false
  positives across dark tree scrub image-wide (dark pixels where noise makes
  R,B slightly exceed G). Sample metrics (0.996) understate this because
  negatives are sampled inside the region boxes; the full-image render shows
  it. A higher threshold + component-size filter fixes it (that is exactly
  what the annotation bootstrap did).
- **rule-hsv-box**: precision 1.000 but recall 0.926 — a hue/saturation rule
  cannot capture the desaturated near-white core, so every stroke is hollow.
  Any absolute-color-rule approach must handle the two-tone structure
  (e.g. detect casing, then close morphologically).
- **rgb / mahalanobis-lab**: the clearly weaker representations. Absolute
  tristimulus color confuses dark casing over dark scrub; ~1 k FPs.
- **dtree/rf on lab**: fine on terrain but misclassify parts of white/blue UI
  glyphs (badge "1" text, the user-location marker) as path.

### Which features mattered

Opponent/chromatic axes matter most: LAB `a`,`b` (or equivalently hue) carry
almost all of the signal; the purple casing is far from every terrain color.
Local deltas (pixel − 31×31 mean) add the last ~1–2 %: they suppress dark-
scrub FPs and pull in the white core (which is strongly brighter than its
local background even where absolute white collides with UI chrome). Texture
(σL) and gradient features added nothing measurable. RGB alone is the only
representation that meaningfully degrades.

### Translucency / terrain dependence

Much less severe than feared, and nothing like the ribbon. The stroke is
composited near-opaque: casing RGB varies only modestly across brown grass,
green circles, gray road and dark scrub (roughly ±20 per channel). Terrain
dependence shows up only for absolute-RGB models; hue-based and local-delta
features are insensitive to it. The observed failure axis is not terrain but
**occlusion**: UDisc draws droplet markers, hole badges and basket icons on
top of the path, punching 30–60 px gaps that any reconstruction must bridge
(morphological closing already does).

## Stage 2 — reconstruction

Best two masks (linear-svm[lab+Δ], logreg[full]) → close(disk 3) → open →
drop components < 400 px → skeletonize:

| model | skeleton completeness (≤5 px) | correctness (≤5 px) | components |
|---|---|---|---|
| linear-svm[lab+Δ] | 0.936 | 0.999 | 2 |
| logreg[full] | 0.936 | 0.999 | 2 |

The skeleton traces the entire path; closing bridges the glyph occlusions;
the ~6 % completeness shortfall is local wiggle around bridged gaps, not
missing path. No graph search needed.

## Anecdote (not a generalization claim)

The linear-svm[lab+Δ] model trained on IMG_5612 regions A/B/D, applied
unchanged to IMG_5613 (same round, ~2× smaller zoom), recovers the full
walking path with no visible false positives anywhere on the screenshot
(`walking-path-results/transfer-IMG_5613.png`). One pair of captures of one
round on one course — encouraging, proves nothing.

## Verdict and simplest next step

Promising enough to continue — this is the easy kind of UDisc overlay (like
droplets/badges, unlike the ribbon). The simplest implementation worth
trying, in the existing `landingDropletDetection.ts` idiom (TS, no ML
runtime):

1. per-pixel purple-casing test `min(R−G, B−G) > ~30` (threshold above the
   scrub-noise floor; optionally add the local-mean delta to be safe),
2. morphological close (radius ≈ ¼ stroke width) to fill the white core and
   bridge glyph occlusions,
3. drop small components,
4. skeletonize → simplify to a polyline → feed `AnnotatedRound.walkingPath`
   as a proposal for user review.

Open risks for that step: stroke width scales with map zoom (close radius and
component threshold must be resolution-relative, like the droplet detector's
size bounds); walking-path purple vs. other possible purple overlays on other
courses is unverified — we need more captures before trusting it broadly.
